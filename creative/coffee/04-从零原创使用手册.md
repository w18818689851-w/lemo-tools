# 从零原创使用手册 · 铜版画风格影片（lemo-opuscar / `engraving`）

> 适用：`lemo-opuscar` 的 `styles/engraving`（Copperplate Engraving，铜版画）风格。
> 面向：要在这个风格下**做一部全新片子**的人——不是要改示例片的人。
> 实例母本：`creative/coffee/01-核心文案.md`、`02-影片方案.md`。
> 技术核心：`D:\lemo-tools\lib\style-dna\engraving-authoring-contract.md`（下称**作者契约**，928 行）。
> 风格逻辑：`D:\lemo-tools\lib\style-dna\engraving.md` / `engraving.json`。

---

## 0. 一句话

一部这个风格的片子 = **媒介（引擎 + 硬规则 + 信息语法）** × **你自己的事实**。
媒介可以继承，事实必须原创。**只换 `content.json` 得到的不是新片子。**

## 1. 为什么要从零做

### 1.1 库文档自己说得很清楚

| 出处 | 原文 | 含义 |
|---|---|---|
| `styles/engraving/STYLE.md:117` | "Swapping `demo/content.json` and rebuilding is a technical check that the engine re-flows, **not a way to make a film**." | 换内容重跑只是**技术检查**，不是做片子的方式 |
| `styles/engraving/DEMO.md:3` | "One example among many. **Don't reuse its story, arc, shots, props or timings.**" | 示例的故事、叙事弧、镜头、道具、时长**都不可复用** |
| `styles/engraving/STYLE.md:101` | "You decide subject, details, order, opening, ending, camera path, colour, pacing and music. Use cases are **grammar for the order and duration of information**; build your own timeline from the user's facts." | 用例表是**信息顺序与时长的语法**；用你自己的事实搭你自己的时间线 |

三条合起来是一个意思：**唯一该继承的是「语法」（引擎 + 硬规则 + 事件词表），句子必须自己写。**

### 1.2 「换 content.json」为什么不算做片子

`content.json` 只驱动**文案、数字、颜色、槽位标签**。它**不含**任何几何、时间线或镜头。所以换内容之后：

- 画面主体还是示例的那一个（`subject` 未知时静默回退，见作者契约 §5）——换不掉蜜蜂的轮廓、排线走向、`focus` 取景点；
- 时间线还是示例的 96 BPM 网格、9 拍/7 拍细节、固定尾部 26 拍；
- 镜头路径还是示例的 `followCam → WIDE → frameFor` 那一串关键帧；
- 声音还是示例的配乐段落与拟音。

一句话：**换的是台词，不是电影。**

### 1.3 代价：从零做要付什么

| 项目 | 换 content.json | 从零原创 |
|---|---|---|
| 文案 | 复用示例句式，换名词 | 先查证事实，再写母本 + 旁白（本实例 `01-核心文案.md` 含 21 行事实核查表） |
| 画面主体几何 | 无 | **新写** `subjects/<name>.js`：轮廓、排线、`regions`、`focus`、`ol0` 首笔，全部手搓 |
| 放大细节 | 无 | 新画内嵌图/放大图，或让主体走"实拍式放大" |
| 时间线 | 无 | 新排 13 个镜头拍点、新定细节条数与 role |
| 镜头 | 无 | 新写 `camAt` 关键帧序列 |
| 版面家具 | 无 | 新的站点/海图/罗盘/刻度（本实例 `subjects/chart.js`） |
| 一致性门 | 跑不过（示例片不暴露契约） | 必须自己实现 `LINES` + `probeAt` |

工作量量级差**一个数量级以上**，而且主体几何与镜头是**没有示例可抄**的部分（示例的 `bee.js` 只提供 API 用法，不提供你主题的形状）。

## 2. 六步流程

每一步都写清：输入 → 产出 → 命令 → 验证。

### 第 1 步 主题 → 原创核心文案（母本 + 事实核查表）

- **输入**：一个主题（如"咖啡如何走向世界"）。
- **产出**：`01-核心文案.md`——① 中文母本（讲故事的事实骨架）② 英文旁白表（`id / text / 画面锚点`）③ **事实核查表**（每行事实 + 数值 + 来源）。
- **命令**：无（纯写作）。**先查证再写**：本实例有意排除了"牧羊人卡尔迪发现咖啡""Kaffir 词源"两条流行但无据的说法（见 `01-核心文案.md:109-113`），因为海图/博物志体画面上的每句话都要经得起核对。
- **验证**：每条旁白都能在母本里找到对应事实；每条事实都有来源。

### 第 2 步 选定风格 → 吃透风格创作逻辑

- **输入**：`styles/engraving/STYLE.md`、`styles/engraving/DEMO.md`。
- **产出**：`02-影片方案.md`——用例选择、画面元素清单、镜头表、上色策略、一致性门方案。
- **命令**：无。读 `STYLE.md`（硬规则 §1–§9 + 用例表 §11）、`DEMO.md`（示例片，**只读结构不抄内容**），对照风格档案 `lib/style-dna/engraving.md`（句式/节奏/调性/镜头逻辑/表达习惯/氛围）。
- **验证**：能回答"这个风格的**禁忌**是什么"（填灰、等宽线、淡入滑入、非印刷转场、不透明色、照抄真实图版、复用示例骨架）。

### 第 3 步 读作者契约 → 知道硬约束

- **输入**：`lib/style-dna/engraving-authoring-contract.md`。
- **产出**：自己列出本片的硬约束清单（见本手册 §3）。
- **重点四块**：① §2.2 时间表（**两套参考系**）② §3.3 事件必发集 ③ §1 主体契约（`ol0` / `focus.eye` / `regions`）④ §4 版面安全区（引线 ≥34px 净空、注记 ≤60 字符、380px 上限）。
- **验证**：能一眼指出"哪些东西不能动"。

### 第 4 步 从零写画面模块（新主体 + 新放大细节 + 版面家具）

- **输入**：第 3 步的契约。
- **产出**：`subjects/<name>.js`（导出 `{ink, regions, focus}`）、必要的细节模块、版面家具模块。
- **硬要求**：只 `import * as B from '../engine/burin.js'`；**不要** import `plate/wash/copper`；**不要**自己 `schedule`；组名恰好 `ol0 / ol / h1 / h2 / h3`；`ol0` **恰好一条**长描边；`focus` **必须有 `eye` 兜底键**；主体落在版框安全区、中心 ≈ (960,606)、光来自左上。
- **命令（自检单帧）**：
  ```
  node core/render/still.mjs styles/engraving/demo 30.9 --q "content=content_coffee.json&film=film_coffee&nosub=1"
  ```
  （`still.mjs` 用法见 `core/render/still.mjs:1`；`nosub=1` 由 film 模块决定是否认）
- **验证**：**必须亲眼看图**。`still.mjs` 会在页面报错或缺文件时立即非零退出（`still.mjs:3`），但**几何好不好看只有眼睛能判**——线宽、遮挡、`ol0` 长度、引线是否穿主体。

### 第 5 步 从零写影片模块（新时间线 / 镜头 / 事件 / 字幕）

- **输入**：第 4 步的主体。
- **产出**：`film_<slug>.js`，导出 `makeFilm(C, voiceDur) → { render, DUR, T, EV, subs, dets, cam }`。
- **三件事**：① 按 96 BPM 网格（`BEAT = 0.625`）重排 `T`，**尾部 26 拍相对结构不动**；② `EV` 发出 §3.3 的必发事件；③ **暴露一致性契约**。
- **暴露契约**（页面侧已就绪，见 `demo/main.js:13-14`）：
  - 模块 `export const LINES = [{ id, t0, t1, text, anchors: [{kind, value}] }]` → 页面转成 `window.LINES`；
  - 模块 `export function probeAt(t) { return { texts, stations, roundels, regions, elements, labels } }` → 页面转成 `window.PROBE`；
  - （可选）`export const FILM_META = { id, title, style }` → `window.FILM`。
  - 锚点 `kind` 只有六种：`text / station / roundel / region / element / label`（`lib/consistency.mjs:18-25`）。
- **验证**：`?film=<name>` 能加载；`window.READY` 为 true；`window.LINES` / `window.PROBE` 存在。

### 第 6 步 渲染 + 过闸门

四道闸，缺一不可：

| 闸 | 命令 | 通过标准 |
|---|---|---|
| 出片 | `node D:/lemo-tools/lemo-make.mjs engraving --film film_coffee --q content=content_coffee.json` | 输出 mp4 |
| 一致性门 | `node consistency-check.mjs styles/engraving/demo --q "film=film_coffee&content=content_coffee.json" --out "D:/lemo-films/_consistency/coffee"` | 退出码 0 |
| 配乐对齐 | `python styles/engraving/demo/tools/cuecheck.py` | `mismatches: 0` |
| 人工复核 | 抽帧看图 | 图文对版 |

- 一致性门判定：每条字幕在其时间窗的 25%/50%/75% 三个采样点上，**每条锚点都必须成立**——任一采样点失败即该条失败（专抓"字幕还在、画面已切走"）。**影片没暴露 `LINES`/`PROBE` 时判不通过**，而不是默认通过（`consistency-check.mjs:75-76`）。
- `cuecheck.py` 用 `events.json` 与 `music/cues.json` 逐拍核对，容差 1 帧 @24（`tools/cuecheck.py:1`），并检查静音段 `mix.wav` 峰值。

## 3. 硬约束速查表（不能动的东西）

### 3.1 时间表

- `BEAT = 0.625 s`（96 BPM），`BAR = 2.5 s`。
- **两套参考系混用是时间线错乱的头号原因**：`T.build.*` / `T.title` / `T.d0` 是**绝对秒数**；`T.dEnd` 之后全部是**相对 dEnd 的拍数**。
- **尾部 26 拍结构不可改**：`gather 2 拍 → silence 2 拍 → colour 8 拍 → landing 7 拍 → end 7 拍`（= 16.25 s）。`DUR = dEnd + 16.25`。
- 细节时长：第 1 个 `9 拍 = 5.625 s`，其余每个 `7 拍 = 4.375 s`。
- `DUR` 速查：N=1 → 31.25｜N=2 → 35.625｜N=3 → **40.0**｜N=4 → 44.375。
- role 分配：N=1 → `A`；N=2 → `A,C`；N=3 → `A,B,C`；N=4 → `A,B,C,C`。

### 3.2 `score.py` 写死的相对时序

`TEMPLATE = {'A': 9.375, 'B': 15.0, 'C': 19.375}`（`music/score.py:311`），配乐按 `OFF = push.t − TEMPLATE[role]` 平移段落。段落内部相对偏移**写死**：

| role | ring | travel | land |
|---|---|---|---|
| `A` | push + 1.05 | push + 1.9 | push + 3.4 |
| `B` | push + 0.5 | push + 0.8 | push + 1.8 |
| `C` | push + 0.5 | —（无 travel） | push + 2.1 |

改这些相对值 → 配乐重音与画面错位、`cuecheck.py` 报 BAD。`natsize` 事件必须等于 `T.gather[0]`，尾部 26 拍与 outro 写死的门对齐（`O2 = OUTRO − 23.75`）。

### 3.3 `mix.py` 必发事件集（缺一个就崩）

`mix.py:15` 是 `first = lambda typ: next(e for e in EV if e['type'] == typ)`——**找不到就抛 `StopIteration`，脚本直接死**。

```
必发（否则 mix.py 崩）：
  burin{t,until}  lift{t}  press{t}  peel{t}
  hatch{t,until}  pass{t,g}×4（g = ol,h1,h2,h3 各一条，缺则 KeyError）
  title{t,n,dur}  natsize{t}  landing{t}  tissue{t}  silence{t,until}
  vo{t,id,dur}（每行一条，id 必须对应 voices/<id>.wav，否则读文件抛错）
必发（否则 cuecheck.py 抛 TypeError）：
  push{t,i,role,dur}  ring{t,i}  land{t,i}  （role 为 A/B 时还要 travel{t,until,i}）
按内容量发（缺了只是没声音）：
  burnish  cut  letters  quill  drop{region}  dot
```

### 3.4 枚举与字段

- `i ∈ {0,1,2,3}`（`mix.py` 直接下标 4 元素声像表，越界即崩）。
- `role ∈ {A,B,C}`（`score.py:315` 用它查段落函数，别的值 KeyError）。
- `g ∈ {ol, h1, h2, h3}`。
- `title.n = 标题字符数 + 1`（含句点）。
- 事件按 `t` 升序。

### 3.5 主体契约

- 导出 `{ ink, regions, focus }`。
- `ink` 组名恰好 `ol0 / ol / h1 / h2 / h3`。
- **`ol0` 恰好一条长描边**——跟刀镜头只取第一条（`tipAt` 用 `find`），多条则只跟一小段；长度决定钩子镜头可看性。
- **`focus` 必须有 `eye` 兜底键**——focus 名写错时回退到它，没有就 TypeError。
- `regions` 的 key = 可上色区名，直接对应 `content.json` 的 `colors[].region`；键少则引线自由，键的 `polys` 覆盖整图则引线绕行失败、直穿画面。
- `focus[name].r` 要**比部位本身略大**（留一圈上下文）：圆窗里显示的世界圆盘半径 = `2.4 × r`。

### 3.6 版面 / 圆窗

- 版框 `PLATE = [70,44,1850,1036]`；双线边框 `BORDER`；引线绕行搜索域 `x∈[140,1780] y∈[90,990]`。
- 圆窗半径 `RR = 120`；**槽位按顺序分配**：`SLOT_ORDER = ['UL','LL','LR','UR']`，坐标 `UL[300,300] LL[300,700] LR[1620,700] UR[1620,300]`。
- **`natSlot = SLOT_ORDER[details.length]`**：N=1 天然大小在 LL；N=2 在 LR；N=3 在 **UR**；N=4 **没有**天然大小图。
- 细节注记 `note ≤ 60 字符`（第 3 行会撞下方圆窗）；注记宽 380 是**上限**（右列右边缘只离内框线 1px）。
- 引线净空 **≥ 34 px**。

## 4. 常见失败模式（症状 → 根因 → 处置）

> ★ 先记住一条贯穿全局的结构事实：**这个项目有两份库、两套文件系统**。
> Windows 库 `D:\lemo-opuscar`（渲染 + 事件导出跑在这里），WSL 库 `/home/lemo/lemo-opuscar`（配音 + 配乐 + 混音 + 字幕跑在这里）。
> **新写的画面模块与影片模块只需要 Windows 侧**（渲染与事件导出都在 Windows），
> 但**内容文件必须两侧都有** —— 因为「配音行派生」与 `subs.py` 都在 WSL 侧执行、都要读它。
> 实测：只把 `content_coffee.json` 放在 Windows 侧，WSL 侧的派生命令会 `FileNotFoundError`。
> 同步一条命令即可：
> ```sh
> wsl -d Ubuntu-24.04 -e bash -lc 'cp -f /mnt/d/lemo-opuscar/styles/<slug>/demo/<内容>.json /home/lemo/lemo-opuscar/styles/<slug>/demo/<内容>.json'
> ```
> 更彻底的做法是两侧内容文件保持同一 md5（用 `md5sum` 对一下）。

| # | 症状 | 根因 | 处置 |
|---|---|---|---|
| 1 | 字幕与画面不符，口播窗整体偏 0.2–1.6 s | **跨文件系统**：渲染页初始化时读 `voices/dur.json` 排口播窗，而 `dur.json` 是 WSL 侧 TTS 的产物 | 换内容时必须**先跑配音、把 `voices/*.json` 回传 Windows，再开始渲染**。用 `lemo-make` 会自动做（代价：音频链少一段并行） |
| 2 | 画面是新的、字幕还是上一版文案 | 字幕源没吃到内容参数（生成器走默认 `content.json`） | 用 `--q content=x.json` 让**整条链**换内容；若事件脚本不吃位置参数，显式加 `--q-events content=x.json` |
| 3 | 配音行没随内容派生 | `lines.json` 没按 build.sh 那条"内容 → lines.json"的派生行重建 | 同上；只想换台词不换画面时用 `--lines <file>` 直接指定 `lines.json` |
| 4 | `mix.py` 抛 `StopIteration` | §3.3 必发事件缺项（`first()` 用 `next()`） | 补齐必发集；`pass` 必须四个 `g` 齐全 |
| 5 | `cuecheck.py` 报 BAD | 细节段相对时序被改了（ring/travel/land 偏移与 `score.py` 写死值不符） | 回到 §3.2 的表；`i`/`role` 也别乱写 |
| 6 | 页面 `window.READY` 迟迟不为 true | 模块 import 失败（路径/语法）或缺 `fonts/fonts.css`（`main.js:10` 要预载 Bodoni Moda / Pinyon Script） | 看 `still.mjs` 的报错；确认 `fonts/fonts.css` 存在、用到的新 weight/size 加进 `document.fonts.load` 列表 |
| 7 | 示例片（默认 `?film=`）坏掉 | `?film=` 缺省路径被改坏 | `main.js:5` 是 `q.get('film') || 'film'`——**保持默认回退到 `film.js`**，新片用 `?film=film_coffee` 走 |
| 8 | 一致性门报"未实现契约" | 影片没暴露 `LINES`/`PROBE` | 影片模块要 `export const LINES` 与 `export function probeAt`（`main.js:13-14`）；缺任一个，闸门判**不通过** |

## 5. 可复制命令清单

> 约定：库根 = `D:\lemo-opuscar`；工具根 = `D:\lemo-tools`；新片 slug = `engraving`，片名 = `film_coffee`，内容 = `content_coffee.json`。
> ⚠️ **`demo/build.sh` 不要用来做新片**：它的 events 行（`build.sh:14`）、video 行（`:21`）、still 行（`:24-25`）都**硬编码 `film.js`**，不带 `film=`。它只适合示例片。

```sh
# 0) 站在库根（core/* 的相对路径、page.mjs 的 requireDemo 都按 CWD 解析）
cd /d/lemo-opuscar

# 1) 单帧自检（写主体/调几何时反复跑；必须亲眼看图）
node core/render/still.mjs styles/engraving/demo 12.0 30.9 \
     --q "content=content_coffee.json&film=film_coffee&nosub=1" \
     --out styles/engraving/demo/out/still --prefix cf_

# 2) 手动导出事件表（第 3 个位置参数 = 工作目录，第 4 个 = film 模块名）
#    用法见 tools/events.mjs:1
node styles/engraving/demo/tools/events.mjs \
     styles/engraving/demo content_coffee.json styles/engraving/demo film_coffee

# 3) 配乐 + 混音 + 配乐对齐（★ 以下四条是 **WSL 侧**命令：`.venv/bin/python` 是 Linux 路径，
#    且 python 依赖装在 WSL 的 .venv 里。用 wsl -d <发行版> -e bash -lc '...' 包起来跑，
#    或在 WSL 里 cd 到 /home/lemo/lemo-opuscar 再跑）
.venv/bin/python styles/engraving/demo/music/score.py
.venv/bin/python styles/engraving/demo/mix.py
.venv/bin/python styles/engraving/demo/tools/cuecheck.py    # 必须 mismatches: 0

# 4) 字幕（同为 WSL 侧；位置参数 = 内容文件）
.venv/bin/python styles/engraving/demo/tools/subs.py content_coffee.json

# 5) 出片（本片自己的 --out，避免和示例片抢同一个文件）
node core/render/video.mjs styles/engraving/demo --fps 24 --workers 2 \
     --q "content=content_coffee.json&film=film_coffee" \
     --out styles/engraving/demo/out/video_coffee.mp4

# 6) 一致性闸门（跨 Windows/WSL，退出码 0 = 通过）
node D:/lemo-tools/consistency-check.mjs styles/engraving/demo \
     --q "film=film_coffee&content=content_coffee.json" \
     --out "D:/lemo-films/_consistency/coffee"
```

## 6. 语言版本（中文版 / 英文版）

> 一句话：**一份内容文件 = 一个语言版本**。片子代码不认识「语言」，只认识内容文件里的 `"lang"` 字段——
> 所以「换语言」= 换一个内容文件，画面模块 / 影片模块**一行都不用改**。
> 注册表：`D:\lemo-opuscar\core\lang\lang.mjs`（`LANGS`），**加一种语言 = 在那里加一条**。

### 6.1 `"lang"` 字段驱动什么

| 由 `"lang"` 决定 | 取值来源 | 说明 |
|---|---|---|
| 字体 | `LANGS[code].fonts` | 三档：罗马体 / 手写体 / **拉丁学名字族**。中文字族必须是**字体栈**（`"Bodoni Moda", "Noto Serif SC"`）——只写中文字体的话，标题里的 `Coffea arabica`、图例里的 `1400—1900`、署名里的 `Lemo` 会被中文字体抢走字形 |
| 字距 | `LANGS[code].track` | 逐项：`title / latin / plateNo / series / figName / station / endTitle / credit`。拉丁大写要拉开（`title: 0.16`），汉字天然紧排（`0.30` 是为汉字视觉重心调的） |
| 圆窗编号前缀 | `LANGS[code].labelPrefix` | `FIG.` → `图`（`FIG. 1 · THE FLOWER` → `图 1 · 花`） |
| 站点刻名 | 内容文件的 `stations{站点键 → 译名}` | 站点键是**语言无关的锚点**；缺译名时才回落到风格自带的拉丁刻名 |
| 配音（引擎 / 音色 / 语速） | 内容文件的 `voice{engine, voice, lang, speed}`（`build.sh` 的派生行直接取它）；`LANGS[code].tts` 是 `core/lang` 侧的默认 | en → 不写 `engine`（缺省 `kokoro`），`en-gb / bm_fable / 0.92`；zh → `engine: "indextts"`，`cmn / zh_curator / 1.0`（引擎机制见 §6.5） |
| 字体预载 | `LANGS[code].css` | zh → `/core/lang/fonts-zh.css`（思源宋体子集 + 霞鹜文楷子集，OFL）；en → `null`（拉丁字体已在风格自己的 `fonts.css` 里） |

取语言用 `langOf(C)`（缺省 / 未知一律回退 `en`），预载用 `fontsToLoad(L)`。
影片模块（`film_coffee.js`）在 `makeFilm` 开头 `const L = langOf(C)`，之后**所有**字族、字距、编号前缀都取 `L.*`；
`LINES` 的文本锚点从内容派生（标题、各站刻名），所以换内容文件时字幕锚点自动跟着变。

### 6.2 加一种语言（三步）

1. **在 `LANGS` 里加一条**（`core/lang/lang.mjs`）。键就是 `--lang` 的值，也是内容文件里 `"lang"` 的值：

   ```js
   ja: {
     id: 'ja', name: '日本語',
     css: '/core/lang/fonts-ja.css',
     fonts: { roman: '"Bodoni Moda", "Noto Serif JP"', script: '"LXGW WenKai"', latin: 'Bodoni Moda' },
     track: { title: 0.22, latin: 0, plateNo: 0.10, series: 0.16, figName: 0.10, station: 0.08, endTitle: 0.10, credit: 0.04 },
     labelPrefix: '図',
     tts: { lang: 'ja', voice: '<你装了的那个音色>', speed: 0.95 },
   }
   ```

2. **加字体 CSS**：把子集 woff2 放进 `core/lang/fonts/`，照 `fonts-zh.css` 的样子写一份 `fonts-ja.css`
   （`@font-face` 的 `font-family` 必须与第 1 步 `fonts` 里写的名字**逐字一致**），再把 `LANGS.ja.css` 指过去。

3. **写内容文件**：`styles/<slug>/demo/content_<片名>.<code>.json`（本例 `content_coffee.ja.json`），
   **文件里必须写 `"lang": "ja"`** —— 这是唯一的开关，忘了写就回退 en（画面还是英文排版）。
   同时把标题 / 系列 / 版号 / 细节名与注记 / 图注 / 落款 / 片尾 / `voice.lines[].text` / `stations{}` 全部译好。
   ★ **两侧都要有**（Windows 库 + WSL 库）：配音行派生与 `subs.py` 都在 WSL 侧跑，只放 Windows 侧会 `FileNotFoundError`
   （同步命令见 §4 开头那条 `wsl ... cp -f`）。

### 6.3 `--lang <code>` 怎么用

规则只有一条：**把 `content=X.json` 换成 `X.<code>.json`，并同时送到渲染与事件侧**
（与 `--film` 同理——只送一侧会让事件表 / 字幕 / 配乐停在另一种语言，`cuecheck` 还会拿同一份错事件核成"通过"）。

```sh
node D:/lemo-tools/lemo-make.mjs engraving --film film_coffee --lang zh --q content=content_coffee.json
# 语言版本 zh → 内容文件 content_coffee.zh.json
# 页面参数 渲染 --q 'content=content_coffee.zh.json&film=film_coffee'
```

- **`--lang en` 是空操作**（en 就是「不带语言后缀的那个内容文件」），所以英文版的命令行与加这个选项之前**逐字一致**。
- 找不到 `<base>.<code>.json` → 编排器 `fail`，并把该 demo 下现有的 `content*.json` 全列出来（不会静默退回英文版）。
- `content=` 填的是**基名**：中文版写 `content_coffee.json` + `--lang zh`，不要写 `content_coffee.zh.json`（那会去找 `content_coffee.zh.zh.json`）。
- 先用 `--dry-run` 核对「语言版本 / 内容文件 / 页面参数」三行打印，再真跑。
- **控制台**：`D:\lemo-tools` 控制台的「主题出片」表单里有「语言版本」下拉（**默认中文版**）。
  选项来自 `GET /api/langs?slug=<风格>`——它按上面这条换名规则探测该风格**真的有**哪些语言的内容文件，
  所以没写 `.zh.json` 的风格只显示「英文版」并给一句提示。工单存 `lang`；出片时 `lang=en` **不传** `--lang`，
  `lang=zh` 追加 `--lang zh`。

### 6.4 已知限制（如实写，别当成 bug 去修）

> 断行现在的顺序是：**词典分词**（`Intl.Segmenter('zh')`，浏览器自带中文词典）→ 两行**均分** →
> 三行以上不留**孤字末行** → 行首/行尾**禁则** → 优先在**标点**处断。下面的限制都是这套之后剩下的。

| # | 限制 | 具体表现 | 原因 |
|---|---|---|---|
| 1 | **拿不到 `Intl.Segmenter` 时会退回逐字断行**；通用词典也会切错专有名词 | 退回时「茉莉」被拆成「茉」/「莉」；人名、品牌名、生造词即使有词典也可能被切 | 断行靠浏览器的 `Intl.Segmenter('zh', { granularity: 'word' })` 把同一个词的字**粘成一个整体**（`plate.js` 的 `cjkUnits`），所以正常情况词不会被拆；`new Intl.Segmenter` 抛异常时 `SEG` 为 `null`，退化成「逐字 + 禁则」的老行为。词典是通用的，不认你片子里自造的词 |
| 2 | **中文版跳过 `asr_check`** | 日志里是「[配音 校对] 跳过 ASR —— 该语言不在离线 ASR 的可用范围内」，不是逐行 DIFF | 离线 whisper 小模型对中文实测 **9/9 全 DIFF**（相似度 0.20–0.57），且它的 norm **不归一化「十/百/千」**——含多位数字的行即使转写正确也 FAIL ⇒ 只会刷一屏假警告、掩盖真正的失败。判定按 `lines.json` 里的 `lang`（`cmn` / `ja` 命中即跳过） |
| 3 | **标题后的句点是拉丁习惯** | 中文版标题显示成「咖啡.」 | `film_coffee.js` 写的是 `String(C.title).toUpperCase() + '.'`（版号、拉丁名同理）——中文没有这个标点习惯，但目前是写死的 |

### 6.5 配音引擎：Kokoro（缺省）与本地 Index-TTS 2.5

> 一句话：**用哪个配音引擎，由内容文件的 `voice.engine` 决定，不是命令行开关。**
> 缺省 `kokoro`（离线小模型，`core/tts/tts.py`）；写 `"engine": "indextts"` 就走**本机 Windows 便携版
> Index-TTS 2.5**（`core/tts/tts_indextts.py`，零样本克隆参考音）。
> 脚本：`D:\lemo-opuscar\core\tts\tts_indextts.py`。

**为什么放内容文件里、而不是加个 `--tts` 开关**：语言（`lang`）和引擎（`voice.engine`）是**同一个源头**。
编排器只读内容文件、不额外读命令行 ⇒「换一份内容文件 = 换一整套语言 + 字体 + 音色 + 引擎」，
不会出现「字幕已经中文、配音还走英文音色」这种两侧各说各话。编排器对内容文件**只读**：
读不到该字段就退回 `kokoro`（英文版与其它 42 个风格行为完全不变）。

| | `kokoro`（缺省） | `indextts` |
|---|---|---|
| 实现 | `core/tts/tts.py` | `core/tts/tts_indextts.py` |
| 跑在哪 | WSL 的 `.venv` | Windows 便携版自带的 venv（脚本**自重入**过去） |
| `voice` 取值 | Kokoro 音色名（`bm_fable` / `af_heart`…） | **参考音频**（别名或 wav 路径），**不是**音色名 |
| `speed` | Kokoro 语速 | `duration_factor = 1/speed`（原生改时长、不变调） |
| 联网 | 不需要 | 不需要（模型在本机） |
| 前置条件 | pip 依赖 | 本机装了 Index-TTS 2.5 便携版（默认 `D:/Index-tts/Index-tts_v2.5`） |

**命令（`--dry-run` 实测输出，去掉 `--dry-run` 就是真跑）**：

```sh
node D:/lemo-tools/lemo-make.mjs engraving --film film_coffee --q content=content_coffee.json --lang zh --dry-run
#   语言版本 zh → 内容文件 content_coffee.zh.json
#   配音引擎 indextts（来自 content_coffee.zh.json 的 voice.engine）
#   输出尺寸 1080x1920（比例 9:16）
#  ...
#   页面参数 渲染 --q 'content=content_coffee.zh.json&film=film_coffee' / 事件 (无)
#   3. 渲染  $ node core/render/video.mjs styles/engraving/demo --fps 24 --workers 6 \
#              --size 1080x1920 --out D:\lemo-opuscar\styles\engraving\demo\out\video_gpu.mp4 \
#              --q content=content_coffee.zh.json&film=film_coffee
```

不带 `--lang`（= 英文版）时不会出现「语言版本 / 配音引擎」这两行，渲染参数逐字是
`content=content_coffee.json&film=film_coffee` —— 即 **`--lang en` 不传 `--lang`**，英文路径零影响（见 §6.3）。

**音色怎么给**（`resolve_voice()`，`tts_indextts.py:103-126`；可用清单由 `available_refs()` 现扫目录得出，已核实）：

| 写法 | 含义 |
|---|---|
| `zh_curator`（默认） / `zh_curator_alt` | 内置别名，分别映射 `voice_12.wav` / `voice_06.wav`（两个都在） |
| `voice_01`–`voice_09` / `voice_11` / `voice_12` | 官方参考音名（正则 `voice_\d+`），到 `INDEXTTS_REF_DIR` 下找同名 `.wav`。**目录里实测没有 `voice_10`**，写它会直接报错并列出可用清单（别照「01–12」的直觉写） |

★ 「提示里承诺的必须真的存在」：报错文案**不写死区间**，而是现扫目录列真实文件名——所以以后往目录里加/删参考音，提示会自动跟着变。

它录得太响，克隆输出 9 条全部顶到满刻度削波（削波不可逆）。

**内容文件里怎么写**（`styles/<slug>/demo/content_<片名>.zh.json`）：

```json
{
  "lang": "zh",
  "voice": {
    "engine": "indextts",
    "lang": "cmn",
    "voice": "zh_curator",
    "speed": 1.0,
    "lines": [ { "id": "title", "text": "图版一。……" } ]
  }
}
```

`voice.lines[].text` 同时就是**字幕源**（画面 / 字幕 / 事件 / 配音两侧同源，见 §6.3）。

**★ 跨宿主路径（踩过坑，改这个脚本前必读）**

1. **从 WSL 启动也能工作**：编排器的音频链路在 WSL，它调的就是这个脚本；WSL interop 可以直接执行
   `/mnt/d/Index-tts/.../python.exe`。所以外层用 `host_path()` 把 `D:/…` 换成 `/mnt/d/…` 做
   「存在性检查 / 起进程」，再用 `win_path()` 反向转回去。
2. **但传给内层（Windows python）的参数必须是 Windows 路径** —— 那个 python 认 `D:/` 不认 `/mnt/d/`。
   所以**输出目录要落在 Windows 能写的位置**（编排器传 `$LEMO_DEMO_WIN/voices`）；脚本的 `win_path()`
   会把 `/mnt/d/…` 自动转成 `D:/…`，两种写法都行，**但不要给相对路径**（会被当成 WSL cwd 下的路径，
   转不过去）。产物落在 Windows 侧还有第二个原因：渲染页读的 `voices/dur.json` 就在那儿。
   写完再由编排器把 wav **拷回 WSL** 的 `voices/`，因为 `mix.py` 在 WSL 跑、要用那一份
   （`lemo-make.mjs:2099-2112`）。
3. **外层不能对 Windows 路径调 `os.path.abspath`**：在 Linux（WSL）上它会把 `D:/x` 当成**相对路径**，
   拼成 `/home/lemo/lemo-opuscar/D:/x`，内层再变成 `\\wsl.localhost\…\D:\x` → `makedirs` 报
   **`WinError 161`**（实测踩到过）。脚本用 `as_local()` 只对「本来就是本宿主路径」的输入做 abspath。

**自重入与批量**：外层进程只做校验 + 路径转换，再用便携版自带的 venv python **重新执行自己**
（靠环境变量 `_LEMO_INDEXTTS_INNER=1` 分辨内外层）；内层**一次加载模型、批量合成全部行**。
**不要逐条调用**（逐条 = 每条都重新加载 3.2 GB 模型）。
**实测（2026-10，本机）**：9 条真实台词 —— 模型加载约 **25 s**，之后每条约 **30 s**（RTF ≈ 6.5），
合计约 **4 分钟**（脚本注释里写的「加载一次要 1–2 分钟」是更保守的估计）。
不走便携版 CLI 的 `batch` 子命令，是因为它的 `cli_v2.py` 走旧推理路径（`indextts.infer_v2`，
没有 `lang` / `duration_factor`），会丢掉 checkpoint 里的 `lang_embedding` / `spk_emb_proj`，
合成结果不可用（`tts_indextts.py:37-43`）。
输出 `out_dir/<id>.wav`（22050Hz 单声道 16bit，去首尾静音）+ `out_dir/dur.json`，接口与 Kokoro 完全一致，
下游 `mix.py` / 影片页面不用改。

**可配置环境变量**（改这里，别散落硬编码）：`INDEXTTS_HOME`（默认 `D:/Index-tts/Index-tts_v2.5`）、
`INDEXTTS_APP`、`INDEXTTS_PYTHON`、`INDEXTTS_REF_DIR`、`INDEXTTS_ENGINE`（`v2_5`|`v2`，默认 `v2_5`）、
`INDEXTTS_QUANT`（默认 `bf16`）、`INDEXTTS_DEVICE`（空 = 自动）、`INDEXTTS_TIMEOUT`（默认 3600s）。

**与 `asr_check` 的关系**：中文（`cmn`）/ 日文（`ja`）会**跳过**离线 ASR 校对（whisper 小模型对中文实测
9/9 全 DIFF），判定按 `lines.json` 里的 `lang`（见 §6.4 第 2 条）。

## 7. 输出尺寸（宽高比 / 自定义像素）

> 一句话：**尺寸的唯一来源是 `D:\lemo-opuscar\core\render\size.mjs`**（`RATIOS` / `DEFAULT_RATIO` /
> `parseSizeSpec` / `resolveSize`）。编排器与控制台都从这里取，「选一个比例 → 一对偶数像素」只算一遍。
> **默认 9:16** —— 任务没有明确指定输出尺寸时，按 9:16 导出。

### 7.1 可选清单与默认值

| 比例 | 含义 | 推导像素（长边 1920） | 备注 |
|---|---|---|---|
| **9:16** | 竖屏 | **1080 × 1920** | **默认项**（`RATIOS` 第一条，也是 `DEFAULT_RATIO`） |
| 16:9 | 横屏 | 1920 × 1080 | 与库里 43 个示例片的原生构图一致 |
| 3:4 | 竖版 | 1440 × 1920 | |
| 4:3 | 横版 | 1920 × 1440 | |
| 1:1 | 方形 | 1920 × 1920 | |
| 自定义 | 任意像素 | 你填的 `宽x高` | 两边都必须是 **偶数**、**96–8192**（H.264 `yuv420p` 要求偶数边长；下限 96 是渲染器的实测几何下限 —— 更小的尺寸圆窗半径会算成负数、渲染器直接崩，见库侧 `core/render/size.mjs` 的 `MIN_SIZE`） |

换算规则：`长边 = 1920`，`s = 1920 / max(宽,高)`，两边再就近取偶数。
所以 9:16 → `s = 1920/16 = 120` → `9×120, 16×120 = 1080×1920`。

### 7.2 `--ratio` / `--size` 怎么用

```sh
# 默认（9:16）—— 出片流程会**显式**带上 --ratio 9:16
node D:/lemo-tools/lemo-make.mjs engraving --film film_coffee --q content=content_coffee.json --ratio 9:16
#   → 输出尺寸 1080x1920（比例 9:16）

# 预设比例
node D:/lemo-tools/lemo-make.mjs engraving --ratio 4:3        # → 1920x1440
# 自定义像素（优先级最高，压过 --ratio）
node D:/lemo-tools/lemo-make.mjs engraving --size 1080x1920   # → 1080x1920
# 非法比例 → 编排器报错并列出可用比例
node D:/lemo-tools/lemo-make.mjs engraving --ratio 7:5        # → fail，列出 9:16 / 16:9 / 3:4 / 4:3 / 1:1
```

- **优先级**：`--size` > `--ratio` > `DEFAULT_RATIO`（9:16）。两个都不给 = 默认 9:16。
- 先用 `--dry-run` 核对打印出来的「输出尺寸」那一行，再真跑。
- **控制台**：`D:\lemo-tools` 的「主题出片」表单里有「输出尺寸」下拉（**默认 9:16**），
  选项来自 `GET /api/sizes`（清单仍是库侧 `size.mjs` 的 `RATIOS`，前端不硬编码）。选「自定义尺寸…」
  会出现宽 × 高两个数字框，非法值（奇数 / 越界）会**禁用「生成工单」**并给出提示。
  工单存 `ratio` / `size`；出片时控制台**总是显式**传一个尺寸参数：
  有自定义像素就传 `--size <WxH>`，否则传 `--ratio <比例>`（**连默认的 9:16 也传**）。
- ★ **出片前的「会被裁切」警告**（防呆）：如果你选的尺寸**不落在这个风格影片真的能构图的那些比例上**，
  表单会立刻弹出一条橙色警告（例：「⚠️ 科幻全息界面（hologram-hud）的影片未适配 比例 9:16（1080×1920）：
  出这个尺寸画面会被裁切，建议用 16:9」）。**它只警告，不禁用出片** —— 你仍然可以坚持出，
  只是提前知道画面会被裁。同一条警告也出现在工单列表的每一行（鼠标悬停看完整说明）。
  判据与怎么自查见 §7.5。

### 7.3 为什么「默认 9:16」放在出片流程，而不是低层工具

`still.mjs` / `video.mjs` 是**低层渲染工具**，全库 43 个风格的 `demo/build.sh` 都直接调它们，
而且**都不传 `--size`、全按 1920×1080 构图**。把低层默认改成 9:16，会让那些示例片**当场全坏**。
所以：

- 低层工具 `takeSize` 的默认**仍然是 1920×1080**（历史行为，别动）；
- **「默认 9:16」只在出片流程生效**（`lemo-make.mjs` 编排器 + 控制台），那里会**显式**把尺寸传下去。

★ 与「语言」的一处不同：`--lang en` 是**不传**的（为了让英文版命令行与加语言功能之前逐字一致，有历史包袱）；
尺寸是**新功能、没有历史包袱**，所以默认值也**显式传** —— 命令行自解释，以后改默认值也不会行为漂移。

### 7.4 怎么查「某个风格支不支持这个比例」（出片前必看）

影片的画布布局是**逐风格**改造的：改造过的影片从视口（`opts.W` / `opts.H`）重排版面，竖屏是**真竖版
构图**；**没改造过**的影片按 1920×1080 的绝对像素画，给别的尺寸会被**裁切**（不是重排、也不是留黑边）。
判断一个风格支不支持某个比例，**只有两条路**，都以影片源码里的 `aspects` 声明为唯一判据：

| 怎么查 | 怎么看 |
|---|---|
| **① 控制台（推荐）** | 「主题出片」表单里选好风格 + 尺寸，警告出现 = 不支持（会被裁）；不出现 = 支持。工单列表/详情里也有同一条。控制台是**读影片源码文本**探测的（影片模块是浏览器 ESM，node 不能 import），探测不到就按「只支持 16:9」算。也可以直接问接口：`GET /api/aspects?slug=<风格>[&film=<影片模块>]` |
| **② 看影片源码** | 打开 `D:\lemo-opuscar\styles\<slug>\demo\<film>.js`，看 `export const FILM_META = { …, aspects: [...] }`。列出的比例 = 这部影片**真的能正确构图**的那些；**没有 `aspects` 这一项 = 只支持 16:9**（= 没改造过）。 |

★ 语义（全库约定，写在 `film_coffee.js` 的 `FILM_META` 上方）：`aspects` 列出「这部影片真的能正确构图」
的比例；**缺省 = 只支持 16:9**。`film_coffee.js` 声明的是 `['16:9', '9:16', '3:4', '4:3', '1:1']`
（五个比例都实测过：版框完整、四张圆窗标签不重叠、海图长条不溢出、字幕在画面内）。

★ 一处**乐观**的地方（如实写）：一个风格的 `demo/` 下可能有好几部影片模块（`film.js` 是页面默认的那部，
`film_coffee.js` 是另做的）。控制台在**建单时**只知道风格、不知道将来跑哪一部，所以取的是该 demo 下
**所有影片模块的并集**；等工单有了 `--film <name>`，就**只按那一部**判（更精确）。所以可能出现
「建单时没警告、工单详情里却警告」——那不是矛盾，是后者更准。

### 7.5 已知限制（如实写，别当成 bug 去修）

| # | 限制 | 具体表现 | 原因 / 怎么办 |
|---|---|---|---|
| 1 | **影片布局的自适应是逐风格做的** | 只有 `engraving` 的 `film_coffee.js` 已声明支持 5 个比例；其余风格的影片模块**都没改造过**（`aspects` 缺省 = 只支持 16:9），在非 16:9 下会被裁切 | 渲染器截的是浏览器视口（`page.screenshot()`），页面必须让 canvas 跟着视口走。**出片前用 §7.4 的两条路查**（控制台会直接警告）；要真的支持，得按库侧 `MAINTAINING.md`「让影片支持多比例」改造影片模块 |
| 2 | 自定义像素只做「偶数 + 96–8192」的语法校验 | 比如 `2000x2000` 能过语法，但它是不是被裁由影片的 `aspects` 决定 | 尺寸只决定**视口**；构图是否适配是影片模块的事。控制台的警告是按**实际像素的宽高比**跟 `aspects` 比（2% 容差），所以自定义尺寸也会被核到 |
| 3 | 比例清单与控制台的显示都依赖库文件 | 读不到 `core/render/size.mjs` 时，控制台**降级成只剩默认 9:16**（并如实上报），不静默用一份自造的比例表 | 与 `lib/langs.mjs` 同一条纪律：清单的权威来源只有库，控制台只做只读代理 |
| 4 | 构图能力是**文本探测**，不是求值 | 影片模块里若把 `aspects` 写成运行时拼出来的表达式（不是字面量数组），探测不到 | 这是**有意的**：影片模块是浏览器 ESM，node import 不了。所以约定 `aspects` 必须是**字面量数组**（见 §7.4 与 `film_coffee.js` 的写法） |
