## 四、关键机制：一致性闸门怎么落的

用户要求「全程保证字幕、语义、画面三者完全匹配统一」。做法不是眼看，而是把它变成**会失败的闸门**：

1. 影片页面暴露 `window.LINES`（每条字幕的时间窗 + 原文 + **语义锚点**）与 `window.PROBE(t)`（t 时刻画面上的结构化事实：已刻出的文字 / 已刻名的站点 / 已在槽位的圆窗 / 已落色的色区 / 画面元素 / 已刻好的标签）。
2. `D:\lemo-tools\consistency-check.mjs` 在该条字幕时间窗的 **25%/50%/75%** 三个采样点逐条断言；**任一采样点不成立即判该条失败**（专抓「字幕还在、画面已经切走」）。
3. 影片**没有**暴露 `LINES`/`PROBE` 时判**不通过**（不是默认通过）—— 示例片就跑不过这一关，这是设计如此。

**实测**：示例片 → `不通过 0/0` + 两条「未实现契约」备注（管路正常）；本片 → **`通过 9/9`**。

例如第 5 条字幕「Yemen drank it by the fifteenth century. One port, Mocha, was the only door.」的时间窗内，画面上海图长条里 **`MOCHA` 的刻名与站点环正在刻出** —— 这是「图文对版」的可核验形式，而不是印象。

## 六、本轮修掉的真实缺陷（都不是猜的，都有实测证据）

### 编排器（`lemo-make.mjs`）——「内容只换一半」这一类缺陷的第 3、4 次出现

| # | 缺陷 | 根因 | 修法 |
|---|---|---|---|
| 1 | **字幕源是旧文案**（画面/配音换了、`.srt` 没换） | `buildShArgs()` 见到未映射的 `$C` 就返回 null ⇒ `subs.py` 被**零参数**调用、回落默认内容 | 把 `eventsArgTemplate` 通用化为 `posArgTemplate`，字幕生成器共用同一套位置参数模板 |
| 2 | **Windows 侧 `voices/dur.json` 永不刷新** ⇒ 页面按旧时长排口播窗（偏差 0.2–1.6 s） | `dur.json` 由 WSL 的 TTS 生成，读它的页面跑在 Windows；全仓 20+ demo 的页面读它 | 换内容时**先跑「只到配音」的前置阶段**，把 `voices/*.json` 回传 Windows，**再**开始渲染 |
| 3 | **配音行不随内容派生** | `build.sh` 第一步就是从内容文件派生 `lines.json`，编排器不跑这步 | 新增 `linesDerivation()`：**照抄 build.sh 那一行**，只替换内容槽 |
| 4 | **上一版「配音前置」时序仍然错**（渲染没等配音） | 前置写在 `audioP` 的 IIFE 里，而 `audioP` 与 `renderP` 两个 IIFE **同时启动** —— 渲染并不等它。后果有两层：口播窗错，**且一致性闸门会拿同一份错时长自洽地假通过** | 把前置提成两个 Promise **建立之前**的独立 await；日志实测已变成 `VOICE_DONE → ✓ dur.json → Windows → 渲染` |
| 5 | 新增 `--lines <file>` 与 `--film <name>` | —— | `--film` 必须**同时送到事件侧**（否则事件表还是示例片的，`cuecheck` 会「核同一份错事件」而假通过） |

**踩坑记录**：shell 的 `${VAR:-default}` **会撞上 JS 模板字符串插值**（实测 `SyntaxError: Missing } in template expression`）。该文件里一律只能用 `$VAR`，默认值靠 JS 侧注入 `export VAR='...'`。

### 影片模块（`film_coffee.js`，智能体产出 + 我复核）

- 圆窗标签被植株叶片压住 / 注记第 3 行被下一张标签吃掉 → 植株缩小、圆窗挪到四角、标签落位重算
- **片尾卡在复制示例片且带明令禁止的署名**（`DEMO.md:80`：「a user's film carries no **LemoLab** credit and no **copy of this card**」）→ 换成 colophon，硬编码署名全部删除
- 引线横穿整版 → 改为带折弯的折线
- `KENYA` 刻名被岸线穿过 → 加纸色底衬 + 纵向偏移（`JAVA` 同）

### 跨文件系统（这一类第 4 次出现）
`content_coffee.json` **必须同时存在于两份库**：配音前置的 `linesDerivation`（WSL 执行）与 `subs.py`（WSL 执行）都要读它。只放 Windows 侧会 `FileNotFoundError`。已写进使用手册。

## 七、已知未解决项（如实列出，不粉饰）

1. **枝顶那枚纵剖果**：`subjects/coffee.js` 在主枝顶端画了一枚纵剖果实（约 115 px 宽 = 真实果实的 4 倍），既与 FIG. 2 圆窗功能重复、又与同图的真实果实尺度矛盾。修它要改 `subjects/coffee.js`（该模块作者已停手），本轮未修。
2. **引线仍会穿过植株**：已从「横穿整版的长直线」改成折线，但四条引线的终点仍在植株内部，线会压在叶上。理想做法是按 `film.js` 的 `d.wp` 绕行机制做 clearance 搜索。
3. **转场瞬间的标签出框**：在细节段推近/拉远的过程中，个别标签会短暂超出画面（到达阅读框后完整）。一致性闸门按 25/50/75% 采样，这个瞬态不在采样点上。
4. **混音峰值 −1.103 dBTP**，未达 −1.2 dBTP 目标（mux 已给出警告，不影响播放）。
5. **时间线的事件语法是继承的**：`score.py`/`mix.py`/`cuecheck.py` 要求同一套 22 类事件与同一相对时序（这是配乐能复用的前提），所以事件类型序列的 LCS 占比 79.2% —— 变的是内容与编排，不是语法。若要连语法也换，需要另写配乐。
6. **咖啡页 `window.READY` 耗时波动大**（20 s ~ 180 s+）：已诊断清楚**不是页面慢**（页面自身只 594–744 ms），而是环境抖动（并发争用/冷盘/杀软）。已把 `chart.js` 的 `formTone` 分辨率 440→220（省 ~290 ms，SSIM 0.983 目视无差别）。
7. `content_bmupqlwah-1.json`（早前那份「换内容重跑」的内容文件）与 `.console-archive-*` 归档仍留在盘上，未删。
