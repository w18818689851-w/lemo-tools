## 1. 风格说明

**是什么**：一部看起来、听起来、并且**行为上**都像 90 年代主机 RPG 的短片——**320×180 原生像素**、×6 最近邻放大到 1080p、受限的**索引调色板**、渐变一律用**有序抖动**而不是混合；故事用游戏自己的语法讲：**对话框配头像、菜单、状态条、战斗消息、存档文件、获得道具的小号角**（`STYLE.md:6-12`）。角色是约 20–34px 高的**精灵**，在少数几帧里动；脸部表演交给 **32×32 头像**。

**不是什么**（最容易做错的邻居风格）：不是 **HD-2D**（没有景深、没有泛光、没有实时光照）；不是 **CRT 怀旧**（没有扫描线、没有颗粒、grain = 0）；不是**戏仿**——它认真地把游戏的系统当成一种表达感受的语言（`STYLE.md:14`）。参考只借语法：绝不使用真实游戏的名称、角色、UI 框、字体、logo、旋律或音效。

**什么时候用它**：内容里**藏着一个游戏系统**——产品发布是「获得新道具」（号角、道具框、数值对比）、告别是一个永不被覆盖的存档位、职业生涯是一张升级画面、一座城是一张大地图加存档点（`DEMO.md:28`）。适合游戏预告、回顾、怀旧（`style.json#uses`）。

**一句话内核**：调色板就是情感——色深、褪色与调色板交换都是叙事工具，整块换表，绝不用 alpha。

**边界**：撑不起**写实质感**内容（没有照片级细节位）、**密集数据**内容（状态条不等于图表）、**细腻表演**内容（精灵脸只有一个像素的眼睛，情绪只能靠头像叠加层与游戏动作）、**需要连续运镜**的内容（相机必须整数像素、逐帧动，做不了平滑长镜）。

## 2. 画面构图

- **镜头数与画幅**：分年代/记忆分段，段内各有自己的镜头（`DEMO.md:34-42`）：开场走廊长侧卷轴、菜单锁定框、回忆宽景、战斗侧视、门槛背视、纪念碑整数像素仰摇。全片 54.50s / 1308 帧 / **原生 320×180 索引帧缓冲 ×6 最近邻 = 1920×1080（16:9）**，24 fps；`styles/pixel-rpg` 没有 `aspects` 声明，**原生只支持 16:9**（★ 2026-10-04 复核、**2026-10-06 实渲复核更正**确认：本风格无视口 / 外壳适配，非 16:9 下画面被**裁切**，见下）。
- **主体位置与占比**：开场走廊里主角很小（约画面高的 **1/6**），侧卷轴带 **4 层视差**（远墙拱窗 0.35×、柱廊与旗与火把 0.7×、地面伪透视 1×、黑色前景柱 1.6×）。菜单镜头把 **UI 放在左侧三分之一**，主角与道具留在右侧可见（`DEMO.md:37`）。
- **负空间 / 留白**：留白由**黑前景柱与暗石墙**承担，量小——帧内几乎处处有内容；真正的「空」是褪色的现在段（f01/f19：整帧只剩蓝灰 7 阶，几乎没有饱和色）。对话框占底部四分之一，**地板线必须在框顶之上**（`STYLE.md:98`），样片把地板线放在 y=128（原生坐标）。
- **图层叠放顺序**（从底到顶）：索引帧缓冲（先按年代画原生内容）→ 视差层（每层**各自取整**偏移）→ 精灵与道具 → 索引步进光照（`LIGHT[]`/`DARK[]` 表 + Bayer 阈值辉光环）→ UI 窗口（对话框 / 顶窗 / 状态条 / 菜单）→ 调色板查找表出图 → ×6 最近邻。整块调色板可在**一帧内**换掉，因为画面存的是索引（`px.js:1-2,104-159`）。
- **安全区**：对话框 y 134–176（原生）占底部四分之一，站立的角色必须留在 y=128 之上；战斗时消息走顶部细窗，**菜单要留出可见的动作区**（`STYLE.md:64`）。
- **本风格不能出现的构图**：任何**非整数像素**的相机位移或子像素插值；任何**alpha 淡化**；HD-2D 的景深/泛光/实时光照；CRT 的扫描线/噪点/颗粒；把满彩场景**事后量化**成 4 色（低年代必须原生画）；侧视图里让手持道具挡住脸（要换成后手）。

**在 9:16（产品默认）下的表现 —— ★ 2026-10-06 复核更正：本风格**没有任何视口 / 外壳适配**，非 16:9 下画面被**裁切**（丢约 44% 画面），故如实跳过，仍只支持 16:9。**

- **实测事实（2026-10-06）**：画布尺寸**写死在 HTML** —— `demo/index.html:4` `<canvas id="c" width="1920" height="1080">`；呈现也写死 —— `px.js:157` `show() { o.drawImage(lo, 0, 0, W * SCALE, H * SCALE); }`（`W=320, H=180, SCALE=6` ⇒ 恒 1920×1080）。整个 `demo/` 目录**零视口感知**（`grep -rn "innerWidth|innerHeight|clientWidth|clientHeight|devicePixelRatio|resize" styles/pixel-rpg/demo/` 无命中），`core/render/page.mjs` 也**没有** contain / 注入 CSS 的通用外壳（全文只有 `:66` 的 `newPage({ viewport: { width: w, height: h } })`）。
- **机械证明**：同一 t=10 帧，16:9 视口与 9:16 视口各取**左上 1080×1080 裁切**，两图**逐字节相同（168,973 B）** ⇒ 换视口画布一点没动 ⇒ 9:16（1080×1920）只看得见左上 **1080×1080**，**右侧 840 px + 下方 840 px 被切掉（≈44% 画面）**。
- ★ **更正说明**：原 2026-10-04 记录称「页面外壳等比装入**不裁切**」—— **该外壳在代码中从未存在**（`git log --follow -- styles/pixel-rpg/demo/index.html` 只有 `cfcaa15` 一笔，全文 411 B、无 CSS 缩放、无 JS）。下面的 `k` 算术**保留**（它正是我们**没加**外壳的原因），但定位改为「**假如**给本风格加 contain 外壳会怎样」。
- **约束是什么**：画面是 **320×180 索引帧缓冲 ×6 最近邻 = 1920×1080**，即每个「像素块」在设计帧里**精确是 6×6 px**；`demo/index.html` 声明 `canvas{image-rendering:pixelated}`。整片的一切（Bayer 抖动渐变、棋盘光柱、1px 描边、像素字）都建在这个**整数网格**上。
- **假如加 contain 外壳，`k` 与块尺寸会怎样（前置条件：该外壳从未实现）**：9:16 视口 1080×1920 下，外壳的等比装入系数 `k = min(1080/1920, 1920/1080) = 0.5625`；像素块会变为 **6 × 0.5625 = 3.375 px —— 非整数**。
- **（该假设下的实测）**：`transform: scale()` 下 **`image-rendering:pixelated` 确实生效**（同帧 pixelated vs auto 有 **3.69%** 像素不同：pixelated 只有 30 种颜色、auto 炸成 **1672** 种），所以**不是模糊问题**；但正因最近邻作用在非整数倍上，输出的**等色游程在 3 px 与 4 px 之间交替**（`∈{3,4}` 占 **73.3%**，0% 长度 1），即像素块**不再均匀**——对「整数像素」是本风格的核心约束，这条会破。
- **整数保持的替代方案也否掉**：要让 `6k ∈ ℤ`，须 `k = m/6`；9:16 下又须 `1920k ≤ 1080`，可取的最大值是 **`k = 3/6 = 0.5`**（块 = 3 px），但画面只剩 **960×540 = 竖屏面积的 25.0%**（等比装入本是 1080×607 = 31.6%），留边高达 **72%** 高——那不是「支持 9:16」，是设计退化。
- **其余预设比例同样不整除**：1:1 / 3:4 下 `k` 同为 0.5625（块 3.375 px）；4:3 下 `k = 0.75`（块 4.5 px）。**结论：本风格不适合用页面外壳范式适配任何非 16:9**（且它现在连外壳都没有，实际拿到的是裁切）。要竖版必须把原生帧缓冲改成竖向（如 180×320）**重新构图**，属设计决策，本轮不做。

## 3. 配色体系

| 角色 | 色值 | 用途 | 来源 |
|---|---|---|---|
| 底（主调色板） | ENDESGA-32 共 32 色，如 `#be4a2f #d77643 #ead4aa #b86f50 #a22633 #e43b44 #f77622 #feae34 #fee761 #63c74d #265c42 #193c3e #124e89 #0099db #2ce8f5 #ffffff #c0cbdc #8b9bb4 #5a6988 #3a4466 #262b44 #181425 #68386c #b55088 #f6757a #e8b796 #c28569` … | 全片所有颜色都从这里取；画面存的是**索引** | `DEMO.md:65` |
| 主（受保护色·围巾红） | `#e43b44` / `#a22633` / `#f6757a` 三阶 | **任何调色板效果都不许动**；贯穿全片的线，让年代之间做匹配剪辑 | `DEMO.md:65`、`px.js:5-21` |
| 强调（受保护色·水晶青） | `#2ce8f5` / `#0099db` / `#ffffff` / `#124e89` 四阶 | 存档水晶的四阶平面着色（8 帧/90° 旋转）+ 抖动光晕 | `DEMO.md:77` |
| 4 色表 | `#1f2a1c #4b5e3a #93a263 #d6dba6`（亮度阈值 <60 / <115 / <175） | 最老年代的 4 色，原生画在 **160×90** 再放大 | `DEMO.md:69` |
| 8-bit 表 | 15 色，含 `#1c2c8c #3c7cfc #94e0fc #b8141c #fc7454 #fcb81c #8c4c1c #2c9c2c #0c4c18 #4c2410` | 必须有**深绿与深棕**，否则夜晚草地会变蓝 | `DEMO.md:68` |
| 褪色（现在） | `lum^0.8 × 7` → 7 阶蓝灰 `#0e0d17 … #c3c9d6` | 「失去之后的现在」的色深 | `DEMO.md:70` |
| 字幕 | 白 `#ffffff` + **1px 夜色暗影**，压在蓝→藏青→夜色的**抖动填充**对话框上；三层圆角边（墨 / 白 / 银） | 对话框就是字幕 | `DEMO.md:81-86` |

- **明度 / 对比规则**：一切明暗走**调色板步进（4 级量化）**，绝不 alpha；`LIGHT[]`/`DARK[]` 把每个索引沿色阶挪一步，辉光是 Bayer 阈值环；**按亮度映射（带 gamma），绝不按排名**——按排名会把场景压成黑（`DEMO.md:70`）。降色子集里**必须保留暖色**（橙、粉、梅红），否则第一步就把夕阳压成一片纯红。
- **禁止出现的颜色**：任何不在主调色板里的颜色（包括事后插值出来的中间色）；任何平滑渐变产生的混色（渐变必须是 4×4 Bayer 抖动）；HD-2D 的泛光白；CRT 颗粒灰。炉火旁的提亮**必须走暖色重映射（绿→棕→锈）**，用通用提亮会把草地变成霓虹绿（`DEMO.md:72`）。
- **同一画面最多几个色相**：由**该段色深**决定——4 色段 ≤4 个平色、8-bit 段 ≤15 色、16-bit 段 ≤32 色；**受保护色不计入年代色数**，它们永远在场。

## 4. 转场规则

- **镜头之间怎么切**：全部走**游戏原生转场**——缩略图放大 + 马赛克（进入回忆，块 10→1 共 0.75s）；马赛克交叉（1→16→1 共 0.8s，**在峰值处换调色板**）；**遇敌旋涡**（极坐标扭转随 `s^1.6` 增长 + 马赛克 + Bayer 溶解到白，0.8s）；屏幕震动（8 帧内 3–2–1 px）；调色板步进淡入淡出（4 级量化）（`DEMO.md:47`、`main.js:174-205`）。
- **有没有叠化 / 闪白 / 擦除 / 定格**：**没有溶解、没有 alpha 淡化**（`STYLE.md:47`）。有**白闪**——遇敌旋涡末尾 Bayer 溶解到白、以及 49.5 的高潮白闪硬切；有**调色板步进淡化**（4 级，不是连续渐变）；有**屏幕震动**；有**保持不动**（调色板塌缩时画面不切也不动，用色深表达失去，`STYLE.md:60`）。
- **硬切点怎么定**：切点挂在**各段自己的 BPM** 上——A 80、B 102.857、C 6/8（附点 81.08）、D 160、E 66.667、G 120、H 80；关键锚点 chime 0、title 2、vo1 5、menu 8、select 10.25、回忆一 11、回忆二 18、遭遇 25.4、战斗 26.2、KO 29.2、静音 29.2–30.1、塌缩 31.0/31.9/32.8/33.7/34.6、存档 40.3、倾斜 42.1、颜色回涨 47.5、白闪 49.5、尾奏 50.4。
- **转场时长与缓动**：马赛克类 0.75–0.8s；窗口滑入 0.3s（ease-out、整数像素）；震动 8 帧；精灵步进 **8 fps（走路）到 12 fps（火焰、眨眼）**，相机与视差**逐帧动、整数像素**（走路速度 30 px/s ≈ 每帧 1.25 px）。
- **绝对不要的转场**：alpha 淡入淡出；HD-2D 的景深/泛光/实时光照；CRT 扫描线/噪点/颗粒；非整数像素的相机移动或子像素插值；把满彩场景事后量化成 4 色。

## 5. 字幕样式

| 项 | 值 |
|---|---|
| 字体 | **原创可变宽像素字体**（大写高 7、x 高 5、降部 2、行高 10），白字 + **1px 夜色暗影**；`dub` 通路当前退到 Microsoft YaHei（见第 11 节缺陷） |
| 字号（相对画面宽 / 高） | 原生帧缓冲里大写高 7px（180 高）≈ **3.9% 画面高**；`dub` 条目 `fontSizeFactor 0.02963` ≈32px @1080 高 |
| 颜色 / 描边 / 阴影 | 白 `#ffffff` + 1px 夜色阴影；**对话框**才是边框本体：三层圆角边（墨 / 白 / 银）+ 蓝→藏青→夜色的**抖动填充** + 左侧 32×32 头像；**皮肤随年代换**（4 色=浅底深字 160×90；8-bit=黑底白框；16-bit/现在=蓝，随现在褪色、颜色回涨时变鲜艳） |
| 位置 / 安全边距 | 对话框画在**底部四分之一**（原生 y 134–176）；战斗与系统消息走**顶部细窗**；地板线在框顶之上（y=128） |
| 单行字数上限 / 最多行数 | 每屏**最多 3 行**、按像素宽度自动折行，单行约 **40–46 字符**；全句建议 12–72 字符；顶部战报 **6–24 字符、全大写** |
| 出现与消失方式 | **逐字打出**（38–40 字符/秒，旧年代 30 字符/秒），打完 **▼ 以 3Hz 闪烁**；每屏停留 ≥ `max(1.8s, 语音 + 0.6s)`；**下一个框直接切掉上一个**（无淡出） |

- **字幕与旁白的关系**：**对话框就是字幕**，打字速度跟人声走；`.srt` 从同一个 `window.SUBS` 数组导出（`DEMO.md:88`）。本次出片 8 条 srt cue、5 句人声（编号 vo1/vo2/**vo4**/vo5/vo6——**vo3 故意缺号**，对应「只活在文字里、只有 blip 没有配音的角色」，`DEMO.md:24`）。
- **本风格特有的字幕禁忌**：不许长段独白（超过 3 行必须分屏）；不许旁白式全知解说；不许现代网络口播腔、emoji、颜文字；**绝不许**使用真实游戏的专有名词、角色名、UI 框、字体或音效（`STYLE.md:4`）。

**文案+风格通路的底衬落地**：STYLE.md §4 声明「The dialog box is the subtitle, drawn in the framebuffer at the bottom quarter」，但「文案+风格」通路原先只走 `BorderStyle=1`（只画描边与阴影、不画底盒；盒填充字段 `OutlineColour` 被当作描边色用），这层底衬从未画出来。现已切到 `BorderStyle=3`（不透明底盒：盒填充色改用 `OutlineColour`、`Outline` 变为盒内边距，`BackColour` 仍只作阴影色——box 模式下 `Shadow=0`，故该阴影不绘制），渲染参数固定为 `BorderStyle=3`、盒内边距 `Outline=10`（1080 高基准）、`Shadow=0`、盒填充色 `OutlineColour=#00000000`（AARRGGBB，落盘 ASS 为 `&H00000000`）。`Shadow=0`：`BorderStyle=3` 下 ASS 的阴影是一份与底盒几乎完全重叠的整盒副本，会把半透明底衬二次压暗（实测 `hd-2d` 的对比度由 6.00 掉到 3.18）；置 0 后底衬的不透明度如实生效，也与检查器的单层合成模型一致。**底衬色为回退值**：demo 的 band 未定位到绘制函数，无法取 demo 真值，也就无法核验 demo 底衬与本配置字色的对比度是否达标（<3.0），故改用该风格自身的地色/辅色（palette.subtitleBack #FF000000）；字色 #FFFFFF 与该底衬的 WCAG 对比度 **21.00**。

## 6. BGM / 音效特征

- **配乐**：**原创芯片音乐**——12.5/25/50% 占空比脉冲波、4-bit 阶梯三角波贝斯、LFSR 噪声鼓、波表主音；SNES 式回声（3 次抽头约 180/270/370ms、反馈 0.35–0.45、环路里低通约 3kHz）；**一条动机贯穿所有段落，各段做「地区变奏」**。音质跟着色深走：4 色 = 单声道 + 4-bit 音量阶梯 + 11kHz 采样保持；8-bit = NES 式单声道；16-bit = 立体声 + 回声；现在的褪色段 = 同一段音乐被闷住（LP 2.2kHz）。塌缩时**音乐每级掉一层**：和声 → 回声与立体声 → 贝斯 → 只剩一个长方波 → **正好在画面到达现在的灰时静一拍**（`DEMO.md:51-56`）。
- **拟音（foley）清单**：全部程序化合成、按场景年代的色深做 bit-crush——光标与选择提示音、文字 blip（**同伴的更高、5-bit**）、带回声的石脚步、火焰噼啪、魔法微光（三角波琶音）、蓄力（上升方波 + 噪声）、爆发（扫频低通噪声 + 48Hz 闷击，压到 6-bit）、HP 递减 tick、KO 闪烁、**每级色深一次 bit-drop（一次比一次更低更粗）**、存档 tick、门轴研磨（棕噪 + AM 吱嘎）、火把点燃、反向渐强。
- **旁白处理**：**唯一不「芯片」的声音是主角开门前的一次呼吸**（带通噪声、不做 crush），让他在最后一刻变回人（`DEMO.md:58`）。人声 Kokoro `bm_george`、speed 0.9、第一人称、5 句短句；音乐在人声下闪避约 **−7.5 dB**（60ms 起、350ms 放）。本次出片 ASR 校对 5/5 全 OK、mismatches 0；「inn」被 whisper 听成「in」，已用 `asr` 字段接受（`DEMO.md:100`）。
- **响度目标**：**−14 LUFS**。★ 2026-10-03 已补：此前本风格的 `lib/style-dna/pixel-rpg` 档案没有抽出 LUFS 数值——它的 `mix_rules` 只写了「音乐在人声下闪避约 **7–8 dB**（快起慢放，用包络算 duck 曲线）；**母带峰值归一到 0.89 满量程**；grain = 0」（`style-dna/pixel-rpg.md:149`、`style-dna/pixel-rpg.json#sound_palette.mix_rules`），而 **`−14 LUFS` 只出现在 `STYLE.md:74` 与 `DEMO.md:60`**；本次已按这两处源头把「整体 −14 LUFS」补进档案的 `mix_rules`（注明来源），全 43 份档案现在都能解析出响度目标。**补之前「文案+口播」通路会回落到默认 `TARGET_LUFS = −16`，与其余 42 个风格的 −14 不一致**（原记录保留如上）。可核验的替代口径是**母带峰值 0.89 满量程 = −1.01 dBFS**——本次实测 `mix.wav` 峰值 **−1.0122 dBFS**，与 0.89 精确吻合（`logs/pixel-rpg.log:160`）；成片实测 **−14.1 LUFS / LRA 8.3 LU**（`logs/pixel-rpg.log:170-172`）。**真峰值上限**：style-dna 与 STYLE.md 都未给 dBTP 目标；本次成片 ebur128 读值 Peak **0.1 dBFS**、astats 采样峰值 **−1.536 dBFS**（见第 11 节）。★ 口径更正：上述 `Peak 0.1 dBFS` 是 `ebur128` 的 1 位小数读数、口径不同，不能当真峰值引用；**成片真峰值 = `loudnorm` 的 `input_tp`，4× 过采样 = +0.08 dBTP**。 ★ **2026-10-03 已修**：成片已用 `scripts/fix-truepeak.mjs` 音频重混（`-c:v copy`，视频流逐字节未变），真峰值 **+0.08 → −1.72 dBTP**，已在 −1.2 dBTP 交付线内；原 +0.08 dBTP 记录保留为历史。
- **静音策略**：静音 = **真零，连回声尾巴也切掉**。两处窗口实测均为 **−240 dB（数字静音）**：29.2–30.1（爆发之后）与 34.6–35.5（哀歌里的一拍）；score.py 的 KO_silence 段 rms −200 dB（`logs/pixel-rpg.log:100-104,125-126`）。**静音是结构，不是留白。**

## 7. 素材偏好

- **需要什么素材**：几乎**不需要外部素材**。要产出的是：`timeline.json`（唯一时间真值：`dur` / `vo{}` / `sections[]` / `FILES[]`）、`lines.json`（配音脚本）、角色（`sprites.js` 的材质四阶 `[line,dark,mid,light]` + ASCII 头部 + 剪影记号）、道具（用受保护索引做平面着色，水晶 8 帧/90°）、每段的 `fidelity` 与 `bpm`、原创芯片配乐（`music/score.py` 读 timeline）。
- **不需要什么素材**：不需要照片、实拍、矢量素材包、字体文件（字体是 `font.js` 里逐字定义的原创可变宽像素字体）、真实游戏的任何资产；不需要景深/泛光/扫描线/颗粒插件（这些正是被禁的邻居风格）。
- **取景 / 质感 / 偏好**：**320×180 原生**、×6 最近邻（**绝不用双线性**）；渐变只用 4×4 Bayer；光柱是 50% 棋盘 + 25% 边缘（比渐变干净）；精灵骨骼 = 胶囊肢体 + 左上 3 阶明暗 + 每部件一道材质最深内线 + 一圈 1px 全局墨色描边；头像 32×32、3/4 视角、基础脸 + 眼/眉与嘴叠加层。
- **可替代方案**（缺素材时怎么降级而不破风格）：没有 ENDESGA-32 就用任何**约 32 色的自由调色板**，但必须**同时定义受保护色与暖色保留**；没有 SNES 回声就用 2 次抽头（仍是「回声」而非混响）；角色画不出来就**减少姿势数、复用同一套骨骼**，但**绝不能**换成平滑插画的角色或给精灵加抗锯齿；色深表做不出来就**只保留 16-bit 与 4 色两档**（少一档年代仍然成立），但**绝不能**改成「一个滤镜扫全片」——色深必须是真的换查找表。

## 10. 编排规则

- **内容文件字段契约**：`timeline.json` 是**唯一时间真值**——`dur`（总时长秒，demo 54.5）、`vo{}`（`{id:{t,expr}}` 每句人声的起点与表情）、`sections[]`（每段 `{id,t0,t1,bpm/meter/downbeats,key,fidelity,mood,hits,note}`）、`FILES[]`（存档位 `{label,place,time,thumb,lut}`，缩略图各自带一张 LUT）；另有 `lines.json`（`{id,text,sub?,voice,speed}`）与 `voices/dur.json`（`{id:秒}`）。**画面、配乐、混音全从 `timeline.json` 导出，改时间只改这一处。**
- **事件词汇表**（本次导出 **151** 条，`EV` → `mix.py`）：`chime`/`sparkle`、`bed{name,t1,gain}`（环境床 hum/fire/wind）、`step`/`step4`/`stepB`、`flare`/`open`/`open8`/`openUI`、`select`/`cursor`/`slide`、`mosaic{up}`、`cloth`/`hop`、`ward`/`charge{t1}`/`blast`、`tick`/`thud`/`koblink`、`bitdrop{k}`（每级色深一次降位）、`savetick`/`grind{t1}`、`flood`/`ignite{pan}`/`swell{t1}`、`breath{d}`（唯一有机声）、`vo{id}`。
- **时间线契约**：页面契约暴露 `window.render(t)` / `window.DUR` / `window.READY` / `window.EV` / `window.SUBS`（`main.js:63,242-243`）；字幕区间规则 `t1 = max(t1_voice + 0.6, t0 + 1.8)`，可被下一句截断（`main.js:32-41`）；`.srt` 从同一个 `window.SUBS` 导出。
- **新增主体怎么接入**：(1) 新增角色 = 在 `sprites.js` 的 `MAT` 里定义材质四阶 `[line,dark,mid,light]`，写一套 ASCII 头部（side/up/down 视角），并给它一个**剪影记号**（衣摆 / 帽 / 发型）——一套骨骼自动出所有姿势；(2) 新增道具 = 用**受保护索引**做平面着色形状（可做 8 帧/90° 旋转）；(3) 新增年代 = 在 `px.js` 的 `LUT` 里加一张查找表（**从主调色板按亮度映射，带 gamma**），并在 `timeline.json` 的 section 给出对应 `fidelity` 与 `bpm`。
- **换主题时要改哪些文件**：**改 3 组**——(1) `timeline.json`（sections / BPM / downbeats / hits / 静音 / 塌缩步进 / FILES）与 `lines.json`（旁白）；(2) 角色与道具（`sprites.js` 的 `MAT` 与 ASCII 头、`props.js`、`portraits.js` 的表情叠加层）与场景（`scenes.js` / `memscenes.js`）；(3) `music/score.py` 的动机与各段编曲（它读 `timeline.json`，所以**改段数/改 BPM 都会自动跟着走**）。`px.js` / `font.js` / `ui.js` 的**引擎层不动**——这是本风格最关键的复用机制：**换时间线与主体，引擎与色深体系不变**。
- **与 `dub.mjs` 通路的关系**：本风格在「文案 + 风格」通路里是 `derived:true` 的条目，`derivedFrom:["palette@lib/dub-visual.json","category-default(pixel)","contrast-rule(WCAG)"]`。**能生效的参数**：`palette`（bg `#3a4466`、bg2 `#262b44`、fg `#FFFFFF`、accent `#e43b44`、subtitle `#FFFFFF`、subtitleOutline `#00000000`、subtitleBack `#FF000000`）、`bgRecipe`（type **gradient**、stops `#3a4466→#262b44`、texture **none**（★ 2026-10-03 已修，原为 `grain`）、vignette 0.35）、`subtitle`（fontFamily **Microsoft YaHei**、fontSizeFactor 0.02963、marginVFactor 0.13981、marginLFactor 0.06019、outlineFactor **0**、bold false、align 2）、`title`（fontSizeFactor 0.09）、`overlay`（**progressBar true**，其余 false）、`motion`（subtitleFadeIn 0、chapterTransition **cut**）。⚠ 该条目原有 **4 处直接违反本风格硬规则**，其中 `texture: grain` 一处已于 2026-10-03 修复（现为 `none`），余 3 处详见第 11 节。

### 素材缺口
- **每段年代的场景与精灵都要为每个主题重画**：`scenes.js`（走廊 / 门）与 `memscenes.js`（村庄 160×90 / 篝火 8-bit / 战斗 16-bit / 缩略图 / 标题 / 片尾）是人力最重的一块。
- **色深表只有 demo 那一套**：`px.js` 的 LUT 全表（full / faded / gb4 / nes / c16 / c8 / c4 / c2）是为 ENDESGA-32 与这套年代配法算的；换主调色板必须**重算全部 LUT**（按亮度 + gamma），不能沿用。
- **原创像素字体只在 `font.js` 里**：没有第二套字面，也没有粗体/斜体变体；标题靠「同字体 2×」而不是另一款字体。
- **原创芯片配乐**：`music/score.py` 的动机 M 与各段地区变奏是为这个题材写的，换主题要重写动机，且必须保证「一条动机贯穿所有段落」这个结构约束。

### 能力限制
- 精灵脸只有一个像素的眼睛，细腻表情只能靠 32×32 头像的叠加层与游戏动作（跳步、施法、击退、跪、KO 闪烁）表达。
- 相机必须整数像素、逐帧动，做不了平滑长镜或大透视运镜。
- 色深塌缩的每一级都必须**原生画**（不能事后量化），因此每多一档年代就多一套绘制与 LUT 工作量。
- 片长通常 40–90s，由年代段数决定（每段 5–12s）；段数太少讲不出「时间」，太多则每段的建立成本过高。

### 踩过的坑（本机实测）
- 本次出片**完整跑通但有 1 条告警**：`node lemo-make.mjs pixel-rpg --skip-sync --no-preflight --ratio 16:9`，1920×1080、nvenc、24fps、6 workers；渲染 1308 帧用 18s，成片 11.0MB、总耗时 39.8s；**告警是「.srt 沿用旧文件、未重新生成」**。
- **走的是 `--skip-sync`**（`[2]` 段显示「（--skip-sync）」），`--no-preflight` 也开着；TTS **是现跑的**（`[配音 1/1]`），不是预生成配音；ASR 校对 5/5 全 OK、mismatches 0；混流走 **nvenc（GPU）**。
- **音频与渲染并行**跑（`[5]` 段末注「音频与渲染并行完成 · 24.7s」），mix.py 在 WSL 里 6 workers 跑 218 块。
- **「真静音」可被验证**：score.py 报 KO_silence rms −200 dB / peak −240 dB，两处静音窗口 peak 均 −240 dB，`clipped_samples: 0`（`logs/pixel-rpg.log:100-104,125-128`）。
- **「音质跟着色深走」可被验证**：score.py 报各段 8–20kHz 相对能量——褪色的现在 A −48.3 dB、F −35.0 dB（最闷），16-bit 战斗 D −21.2 dB、遭遇 −18.5 dB（最亮），与「现在被闷住、16-bit 立体声最亮」的声明一致。
- 媒介坑（`DEMO.md:93-102`）：**按排名映射调色板会把一切压成黑**（要按亮度带 gamma）；塌缩子集里不留暖色会让夕阳第一步变纯红；8-bit 集缺深绿会让夜晚草地变蓝、炉火旁用通用提亮会让草地变霓虹绿；把满彩场景事后量化成 4 色是一团糊；头发画成光滑圆顶读成头盔、单像素交替读成锯齿噪点（要 2–3 个大发尖）；奶油色束腰读成裸皮；侧视图前手持杖会横穿脸（换后手）；背挂剑横过躯干正面（换腰鞘）；深色木板门读成牢门（要凹面板 + 斜边 + 铆钉 + 门环 + 鼓室）；**负数取模会索引到 `undefined`**（必须 `((n % m) + m) % m`）；对话框盖住底部四分之一却没把地板线抬到框顶之上；受保护色的匹配剪辑要**同时算两侧的屏幕位置**（样片的围巾在两段里都在 (197,104)）；whisper 把「inn」听成「in」（用 `asr` 字段接受，字幕负责消歧）。
- 抽帧层面的一个**复核陷阱**：遇敌旋涡末尾会 Bayer 溶解到**全白**，f12（≈26.0s）抽到的是**纯白一帧**——这是设计内的过渡峰值，不是渲染失败；但孤立地看一张全白抽帧很容易误判为坏帧，复核时要结合 `main.js:189-199` 的时间窗一起看。
